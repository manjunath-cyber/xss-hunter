Reflected XSS in Search Parameter

Endpoint: /api/search | Parameter: query

Critical ▼

Vulnerability Details

Vulnerability Type: Cross-Site Scripting (XSS) - Reflected
CVSS Score: 9.1 (Critical)
Attack Vector: Network
Complexity: Low

Description

The application fails to properly sanitize user input in the search parameter before reflecting it in the API response. An attacker can craft a malicious URL containing JavaScript code that will be executed in the victim's browser.

Proof of Concept

GET /api/search?query=<script>alert('XSS')</script>
Response: {"results": "<script>alert('XSS')</script>"}

Impact

  • Session hijacking through cookie theft
  • Credential harvesting via fake login forms
  • Malware distribution
  • Defacement of user interface
  • Unauthorized actions on behalf of users
✅ Remediation Steps
  • Input Validation: Implement strict whitelist validation for all user inputs
  • Output Encoding: HTML-encode all user input before reflecting in responses
  • Content Security Policy: Implement CSP headers to restrict script execution
  • Web Application Firewall: Deploy WAF rules to detect and block XSS payloads
  • Security Testing: Integrate automated XSS testing in CI/CD pipeline

References

  • OWASP XSS Prevention Cheat Sheet
  • CWE-79: Cross-site Scripting
  • OWASP XSS Cheat Sheet

SQL Injection in User Filter

Endpoint: /api/users | Parameter: filter

Critical ▼

Vulnerability Details

Vulnerability Type: SQL Injection
CVSS Score: 9.8 (Critical)

Description

The API constructs SQL queries by concatenating user input directly without using parameterized queries. This allows attackers to inject arbitrary SQL code.

Proof of Concept

GET /api/users?filter=name' OR '1'='1
✅ Remediation Steps
  • Use parameterized queries/prepared statements
  • Implement input validation and type checking
  • Apply principle of least privilege to database accounts
  • Use ORM frameworks that handle query parameterization

Missing Authentication on Admin Endpoints

Endpoint: /api/admin/settings

High ▼

Description

Administrative endpoints are accessible without proper authentication, allowing unauthorized users to modify critical settings.

✅ Remediation Steps
  • Implement OAuth 2.0 or JWT authentication
  • Validate tokens on every API request
  • Implement role-based access control (RBAC)

Insecure Direct Object Reference (IDOR)

Endpoint: /api/users/{id}

High ▼

Description

Users can access other users' data by simply changing the ID parameter, indicating missing authorization checks.

✅ Remediation Steps
  • Implement proper access control checks
  • Verify user ownership before returning data
  • Use indirect references (UUIDs instead of sequential IDs)
